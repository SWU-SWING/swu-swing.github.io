시나리오 기반 침해사고 분석 보고서: USB 기밀 유출

author: ycl Posted on 2026-07-11 In SWING 활동 회고 series

서론

해당 글은 포렌식 보고서 작성 원칙(추측을 배제한 객관성 유지, 분석 환경 표기를 통한 재현 가능성 확보, 시간 표기 통일, 증거 위주)을 따라 작성되었다. 다만 필자의 포렌식 스터디 당시 분석 실수를 되짚는 취지의 글이니 만큼, 이 글을 읽는 누구나 따라 할 수 있게끔 보편적으로는 보고서에 포함되지 않는 시행착오와 과정 설명을 일부 포함하였음을 밝힌다.

본 분석의 주요 쟁점은 다음과 같다. 첫째, 피조사자 학회원의 노트북에 실제로 USB 저장장치가 연결되었는지 여부를 확인하는 것이다. 이를 위해 setupapi.dev.log와 SYSTEM 하이브의 USB 및 USBSTOR 레지스트리 기록을 분석하였다. 둘째, USB 연결 전후로 내부 기밀 자료에 접근하거나 사용한 흔적이 존재하는지 확인하는 것이다. 이를 위해 Prefetch, LNK, Jump List, NTFS 로그($UsnJrnl/$J, $LogFile, $MFT)를 분석하여 문서 실행·접근·삭제 기록을 시간 순서에 따라 정리하였다. 셋째, USB를 이용한 자료 반출 또는 관련 흔적 은닉 정황이 존재하는지 검토하는 것이다. 이를 위해 Chrome History를 분석하여 USB 사용 흔적 삭제 및 안티 포렌식 관련 검색·열람 기록을 확인하였다. 따라서 본 보고서는 확보된 디지털 증거를 바탕으로 USB 연결 여부, 기밀 자료 접근 정황, 삭제 및 은닉 시도 가능성을 종합적으로 분석하는 것을 목적으로 한다.



본론

1) 시나리오

SWING의 내부 기밀 자료가 외부로 유출되었다. 한 학회원의 노트북을 압수한 초동 조사 결과, 자료가 USB 저장장치로 복사된 흔적이 확인되었지만 해당 학회원은 USB 연결 자체를 부인하고 있는 상황.

2) 사용 도구

  • FTK Imager 8.2.0.26 (https://www.exterro.com/ftk-downloads)
  • Registry Explorer 2026.5.0 (https://ericzimmerman.github.io/)
  • rla 2026.5.0 (https://ericzimmerman.github.io/)
  • LECmd 2026.5.0 (https://ericzimmerman.github.io/)
  • JumpList Explorer 2026.5.0 (https://ericzimmerman.github.io/)
  • NTFS Log Tracker 1.71 (https://sites.google.com/site/forensicnote/ntfs-log-tracker)
  • DB Browser for SQLite 3.13.1 (https://sqlitebrowser.org/)

3) USB 연결 흔적 로그 분석

그림 1. [C:\Windows\inf\setupapi.dev.log]

확보한 디스크 이미지를 FTK Imager에서 열어 setupapi.dev.log를 추출하였다. 본 분석은 setupapi.dev.log 파일을 분석하여 USB 장치 설치 로그에 포함된 정보를 확인하는 것을 목적으로 한다.

그림 2. [setupapi.dev.log 파일 내부 USBSTOR]

setupapi.dev.log 파일 내부에서 USB 저장장치 흔적이 잡히는 USBSTOR을 검색하여 분석한 결과, SanDisk USB 저장장치가 시스템에 연결되어 정상적으로 설치 및 시작된 흔적이 확인되었다.

설치된 USB 정보와 설치 완료 시각은 아래 로그 결과와 같다.


그림 3. [setupapi.dev.log 파일 내부 장치 설치 종료]

아래를 추가로 확인한 결과, dvi: {Install DEVICE exit (0x00000000)}이 출력된 것을 확인하였다. 이는 장치 설치 단계가 종료되었고, 결과 코드 0x00000000로 성공을 의미한다.

또한 dvi: Install Device: Starting device completed. 21:42:30.675 출력을 통해 설치 후 윈도우가 해당 장치를 실제로 사용할 수 있도록 활성화하는 단계를 완료한 사실을 확인하였다.

4) USB 연결 흔적 레지스트리 분석

그림 4. [C:\Windows\System32\config 내부]

Windows의 레지스트리는 여러 개의 hive 파일로 나뉘어 저장되며 핵심 하이브 파일들은 C:\Windows\System32\config 경로에 존재한다. 해당 경로에서 SYSTEM 하이브를 추출했다. (단, 이때 SYSTEM.LOG1 및 SYSTEM.LOG2를 함께 추출한 후 SYSTEM과 같은 경로에 두고 분석하여야 한다.)

그림 5. [SYSTEM 하이브 내부 USBSTOR 검색]

Registry Explorer를 사용해 SYSTEM 하이브를 열어주었다.

내부에서 USB 저장장치 기록을 보는 대표 위치인 USBSTOR을 검색하였지만 CorrentControlSet\Enum\USBSTOR 경로를 찾아볼 수 없었다.

그림 6. [Select 내부 Current 값 확인]

오프라인 SYSTEM 하이브에서 CurrentControlSet이 ControlSet00x에 대응되므로 해당 번호를 확정하기 위해 Select 내부의 Current 값을 확인하였다. Current 값은 1, 현재 분석 중인 ControlSet001과 일치하므로 원하는 USBSTOR를 찾지 못한 것은 위치 문제와 무관하다.

즉 해당 오류는 SYSTEM.LOG1 / SYSTEM.LOG2에 남아 있는 변경 사항을 SYSTEM 하이브에 반영하지 못한 결과이다.

그림 7. [SYSTEM 하이브 경로]

그림 8. [RLA 이용하여 Transaction Log Replay]

위 분석에서 SYSTEM 하이브가 dirty 상태로 확인되어 SYSTEM.LOG1 및 SYSTEM.LOG2를 기반으로 transaction log replay를 수행하였고, 이후 재분석한 clean SYSTEM 하이브에서 USB 연결 흔적을 확인하였다.

그림 9. [RLA 산출물]

그림 10. [clean SYSTEM 하이브 ControlSet001\Enum\USB]

Registry Explorer를 사용해 clean SYSTEM 하이브를 열어주었다.

ControlSet001\Enum\USB에서 VID_0781&PID_5567 하위에 Serial Number 00023711122323170522를 가진 USB 저장장치가 확인되었다. 해당 장치의 Service 값은 USBSTOR이며, Device Description은 USB Mass Storage Device, Friendly Name은 Cruzer Blade로 확인되었다.

따라서 해당 시스템에는 Serial Number 00023711122323170522를 가진 SanDisk Cruzer Blade USB가 2026-02-12 12:42:29에 시스템에 처음 설치(First Installed)되었으며, 동일 시각에 마지막으로 연결(Last Connected)되었다고 판단된다. First Installed와 Last Connected가 동일하므로 USB가 한 번만 연결되었거나 시스템이 꺼진 상태에서 뽑았다는 정황을 뒷받침한다.

이는 setupapi.dev.log의 증거와 정확히 일치한다. (Registry Explorer는 UTC 기준으로 시간을 표현하므로 2026-02-12 12:42:29 UTC + 9시간 = 2026-02-12 21:42:29 KST)

단, Last Removed가 비어 있기 때문에 USB가 분리된 시각은 확인할 수 없다.

그림 11. [clean SYSTEM 하이브 ControlSet001\Enum\USBSTOR]

다음으로 USBSTOR에서 피조사자가 연결한 것으로 추정되는 00023711122323170522 USB 시리얼 번호의 Property Store 속성 카테고리를 살펴보았다.

그림 12. [clean SYSTEM 하이브 ControlSet001\Enum\USB]

그림 13. [clean SYSTEM 하이브 ControlSet001\Enum\USB]

그림 14. [clean SYSTEM 하이브 ControlSet001\Enum\USB]

USBSTOR의 Properties 아래 있는 0064, 0065, 0066 FILETIME 형태의 타임스탬프 값을 분석한 결과 모두 기록된 시각이 2026-02-12 12:42:29로 동일했다. 이는 ControlSet001\Enum\USB First Installed와 Last Connected가 동일했던 결과와 맥을 같이 하며 해당 시각 USB를 한 번만 연결하였거나 시스템이 꺼진 상태에서 연결을 해제한 정황을 뒷받침한다.


5) 유출된 자료 추적 (Prefetch/LNK/Jump List/$UsnJrnl)

그림 15. [C:\Windows\Prefetch\EXCELE.EXE 프리패치]

그림 16. [C:\Windows\Prefetch\WINWORD.EXE 프리패치]

USB 연결 시각은 SYSTEM 하이브의 USBSTOR 및 setupapi.dev.log를 통해 확인하였으므로 이후 Prefetch 분석을 통해 USB 연결 전후에 실행된 프로그램 흔적을 확인하였다.

C:\Windows\Prefetch 경로에서 발견된 USB 연결 시작 일시(2026-02-12 12:42:29 UTC) 직전 프리패치는 EXCELE.EXE(2026-02-12 12:41:26 UTC), WINWORD.EXE(2026-02-12 12:41:28 UTC)이다. 이는 USB 설치 전 엑셀 파일과 워드 파일을 열었다는 정황을 뒷받침한다.

그림 17. [Users\사용자명\AppData\Roaming\Microsoft\Windows\Recent]

다음으로 어떤 파일에 접근했는지 알아보기 위한 목적으로 최근 접근한 것들의 바로가기 파일 목록을 분석하였다. 확인 결과 Users\사용자명\AppData\Roaming\Microsoft\Windows\Recent 해당 경로에서 ‘스윙 CTF’, ‘기밀’, ‘학회원 명단’ 등 수상한 이름이 파일들이 발견되었다. 다만 해당 파일들의 이름만으로 피조사자가 해당 파일을 열어보았음을 확정할 수 없다. 세부 사항을 확인하기 위해 SWING_자료_기밀, SWING_학회원명단, SWING_CTF_2026_문제출제계획서 세 바로가기 링크 파일을 추출했다.

그림 18. [LECmd.exe –f “SWING_자료_기밀.lnk 경로”]

LECmd를 사용하여 SWING_자료_기밀 링크 파일을 분석하였다.
분석 결과 바로가기(.lnk) 파일 자체는 2026-02-12 10:07:02에 생성되었으며, 마지막 수정 및 접근은 12:49:32에 이루어졌다.

한편 바로가기가 가리키는 원본 파일은 2026-02-12 10:06:55에 생성, 마지막 수정 및 접근은 2026-02-12 12:49:32에 이루어졌다.

원본 파일 생성 후 거의 바로 바로가기 파일이 만들어졌으며, USB 연결 시간 12:42:29 (UTC) 이후 약 7분 뒤 해당 파일이 접근되었음을 알 수 있다.

그림 19. [LECmd.exe SWING_자료_기밀.lnk 분석 결과]

추가 분석 결과 바로가기가 참조하는 대상 파일은 C:\Users\been_\Documents\ 경로에 존재하는 것으로 확인되었다. 또한 Volume Information 분석 결과 대상 파일은 Drive Type이 Fixed Storage Media(Hard Drive)인 로컬 저장장치에 위치하였으며, Volume Serial Number는 987FCC5B로 확인되었다.

바로가기 참조하는 SWING_자료_기밀 파일이 피조사자 노트북의 내부 저장 장치에 존재하나, 이를 통해 파일의 확장자를 인식할 수 없고, USB에 복사되었는지 확정할 수 없다.

그림 20. [LECmd.exe –f “SWING_학회원명단.lnk 경로”]

다음으로 SWING_학회원명단 링크 파일을 분석하였다. 분석 결과 바로가기 파일은 2026-02-12 10:07:27에 생성되었으며, 마지막 수정 및 접근 시각은 2026-02-12 12:41:33으로 확인되었다.

한편 바로가기가 참조하는 원본 파일은 2026-02-12 10:07:27에 생성 및 수정되었으며, 마지막 접근 시각은 2026-02-12 12:41:32로 확인되었다.

원본 파일과 바로가기 파일은 동일한 시각(10:07:27)에 생성된 것으로 나타나며, USB 연결 시각인 2026-02-12 12:42:29(UTC)보다 약 57초 이전에 원본 파일이 마지막으로 접근되었다.

그림 21. [LECmd.exe SWING_학회원명단.lnk 분석 결과]

추가 분석 결과 SWING_학회원명단 또한 USB가 아닌 내부 저장장치(HDD/SSD) 에 저장되어 있었다. Volume Serial Number가 일치하므로 SWING_자료_기밀과 같은 드라이브에 저장되어 있었음을 알 수 있다. 또한 대상 파일명은 SWING_학회원명단.xlsx로 엑셀 파일이었고, 해당 파일이 Documents\SWING_자료_기밀 폴더 안에 존재하였음을 알 수 있다.

따라서 SWING_자료_기밀은 폴더였음이 확인되었고, 12:41:26(UTC) EXCEL.EXE 프리패치 실행 직후 12:41:32 ~ 12:41:33(UTC) SWING_학회원명단.xlsx와 이를 참조하는 .lnk 파일의 접근 기록이 확인되었다. 두 기록을 시간상으로 종합하면, Excel 실행 이후 해당 파일이 열람되었을 가능성이 있는 것으로 판단된다.

그림 22. [LECmd.exe –f “SWING_CTF_2026_문제출제계획서.lnk 경로”]

마지막으로 SWING_CTF_2026_문제출제계획서 링크 파일을 분석하였다.

분석 결과 바로가기 파일은 2026-02-12 10:07:06에 생성되었으며, 마지막 수정 및 접근은 2026-02-12 12:49:32에 이루어졌다.

한편 원본 파일은 2026-02-12 10:07:06에 생성되었으며, 생성 직후인 10:07:07에 수정되었다. 마지막 접근은 2026-02-12 12:49:28에 이루어졌다.

그림 23. [SWING_CTF_2026_문제출제계획서 분석 결과]

추가 분석 결과 바로가기가 참조하는 대상은 SWING_자료_기밀 폴더에 저장된 SWING_CTF_2026_문제출제계획서.docx 파일이었다. 저장된 곳은 SWING_학회원명단.xlsx과 동일했다.

링크 파일로 알아낸 타임라인을 한국 시각 기준으로 총정리하자면 다음과 같다.

이러한 사실을 통해 USB 연결 직전 Excel 문서(SWING_학회원명단.xlsx)가 접근되었고, 약 1분 후 SanDisk Cruzer Blade USB가 연결되었으며, USB 연결 후 약 7분 뒤 SWING_CTF_2026_문제출제계획서.docx가 접근되었음을 확인하였다. 이는 피조사자가 USB 연결 전후로 SWING_자료_기밀 폴더의 문서들을 연속적으로 확인한 정황을 뒷받침한다.

그림 24. [Users\사용자명\AppData\Roaming\Microsoft\Windows\Recent\AutomaticDestinations]

이어서 FTK Imager를 이용해 AutomaticDestinations 폴더에서 Windows가 프로그램별로 남기는 최근 사용 파일 목록 기록인 점프리스트를 모두 추출하였다.

그림 25. [Word에서 파일을 사용한 기록]

확인 결과 APP ID fb30db0fee58fac8, Microsoft Office Word x64 아래 Entry에 ‘This PC\Documents\SWING_자료_기밀\SWING_CTF_2026_문제출제계획서.docx’이 기록되어 있었다.

Microsoft Word의 Recent Documents 목록에서 ‘SWING_CTF_2026_문제출제계획서.docx’가 확인되었으므로, 해당 문서가 Microsoft Word를 통해 열람된 정황이 확인된다.

그림 26. [Excel에서 파일을 사용한 기록]

추가 확인 결과 APP ID b8ab77100df80ab2, Microsoft Office Excel x64 아래 Entry에 ‘This PC\Documents\SWING_자료_기밀\SWING_학회원명단.xlsx’이 기록되어 있었다.

Microsoft Excel의 Jump List에 ‘SWING_학회원명단.xlsx’가 등록되어 있는 점을 통해 해당 문서가 Excel 프로그램에서 열람된 정황이 확인된다.

또한 Chrome History 분석 결과 USB 연결 기록 삭제 및 USB 사용 흔적 제거 방법, 안티 포렌식 관련 웹페이지를 검색·열람한 기록이 확인되었다. 이는 USB 사용 흔적을 제거하려는 의도를 시사하는 정황 증거로 판단된다. 다만, 해당 검색 기록만으로 실제 안티 포렌식 행위를 수행하였다고 단정할 수 없다. 특히 사용자가 접속한 웹사이트에서는 USBSTOR, setupapi.dev.log에서의 USB 연결 기록 삭제에 대해 설명하였으나 분석 결과 USB 연결 기록이 존재하였기 때문이다.

현재 확보된 증거만으로는 문서가 실제로 USB 저장장치로 복사되었거나 외부로 유출되었다는 사실을 뒷받침할 수 없다. 하지만 ‘자료가 USB 저장장치로 복사된 흔적이 확인되었지만 해당 학회원은 USB 연결 자체를 부인하고 있는 상황’ 이라는 이번 시나리오에 한해서 현재 확보된 디지털 증거를 종합한 결과 해당 학회원의 진술의 신빙성은 낮다. USBSTOR와 SetupAPI에서 동일 SanDisk USB의 연결 기록이 확인되므로 부인 진술과 디지털 증거가 배치되기 때문이다. 또한 USB 연결 전후의 문서 접근/삭제 기록과 USB 사용 흔적 삭제 관련 검색 기록이 함께 확인되어 자료 반출 이후 관련 흔적을 제거하려는 정황이 존재하는 것으로 판단된다. 따라서 본 분석 결과는 해당 학회원의 진술과 상반되는 디지털 증거를 확인하였으며, USB를 이용한 자료 반출 및 이후 증거 은닉 정황을 뒷받침하는 객관적 근거를 제공한다.

본 사건은 특히 USB를 활용한 정보 유출 사건이다. 따라서 USB 장치 사용 통제 정책을 강화해야 한다. 승인되지 않은 USB 저장장치 연결 차단 및 USB 장치 시리얼 번호 기반 허용 목록 운영을 권고한다. 또한 네트워크 전송 기록, 클라우드 동기화 기록 등 추가 디지털 증거를 확보하여 정보 유출 여부를 종합적으로 판단할 것을 권고한다. 아울러 중요 자료에 대한 USB 사용 통제 및 접근 기록 모니터링을 강화하여 유사 사례를 예방할 필요가 있다.
