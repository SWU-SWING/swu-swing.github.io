[SEED 7월호] CVE-2025-0411: 7-Zip MotW 우회 취약점

author: ycl Posted on 2026-07-21 In S.E.E.D. series

1. 들어가며

CVE-2025-0411은 7-Zip의 Mark-of-the-Web(MotW) 우회 취약점이다. 해당 취약점은 인터넷에서 받은 압축파일 안의 파일은 원래 ‘인터넷에서 온 위험한 파일’ 표시가 따라가야 하지만 특정 상황에서 7-Zip이 그 표시를 내부 파일에 전달하지 못한 문제이다. Windows는 인터넷에서 파일을 다운로드할 때 파일 뒤에 숨겨진 출처 정보인 Zone.Identifier가 붙는다. Zone.Identifier 내부에는 ‘ZoneId’라는 숫자 정보가 존재하며 숫자로 파일의 출처를 구분한다. ZoneId가 3일 경우 이 파일은 신뢰할 수 없는 영역, 즉 인터넷에서 왔음을 의미하며 이는 Windows가 파일을 실행하기 전 보안 경고를 띄우는 등의 행위 판단의 근거가 된다. 그러나 7-Zip 24.09 미만 버전에서 중첩 압축파일(zip 파일 안에 또 zip 파일이 존재하는 구조)을 처리할 때 Zone.Identifier가 추출 파일에 정상적으로 전파되지 않아 Windows 보안 경고를 우회할 수 있었다. 이로 인해 공격자는 악성 이중 압축파일을 사용자에게 열도록 유도하여 내부 실행파일이나 스크립트가 인터넷에서 유입된 파일로 인식되지 않게 만들 수 있게 되었으며, 결과적으로 현재 사용자 권한에서 악성코드 실행으로 이어질 수 있었다. 본 보고서에서는 이를 악성 첨부파일 기반 문서 위장형 공격 사례로 분류하고 취약점의 PoC 구조, Exploit 흐름, 패치 현황을 분석할 예정이다.

2. CVE-2025-0411 공격 사례

CVE-2025-0411는 실제 SmokeLoader 캠페인에서 악용된 사례가 존재한다. 러시아 사이버 범죄 조직은 우크라이나 정부기관·기업 계정으로 보이는 침해된 이메일 계정을 사용해서 피싱 메일을 보내는 형식으로 우크라이나를 공격했다. 공격 방법은 다음과 같다. 우선 공격 집단은 안쪽 압축파일의 확장자를 .doc처럼 보이도록 만들었다. 이는 겉으로는 .doc 문서처럼 보이지만 마지막 c를 일반 라틴 문자 c가 아니라 키릴 문자 c로 만들어 확장자를 속이는 방식이다.(homoglyph attack) 이 안쪽 파일이 실제로는 7-Zip 아카이브였고, 사용자는 거짓 확장자 때문에 문서로 착각해 열도록 유도당했다. 안쪽 압축파일 내부에는 .url 파일이 들어 있었고 이 .url 파일은 공격자 서버의 추가 ZIP 파일을 가리켰다. 나아가 해당 .url 파일도 ZIP 아이콘처럼 보이게 위장되어 있었고 CVE-2025-0411 악용 때문에 MotW 보호가 빠진 상태였다. 이후 다운로드된 ZIP 안에는 PDF 문서처럼 보이는 실행파일, 예를 들면 .pdf.exe 형태의 파일이 있었으며 이것이 실행되면 SmokeLoader 페이로드가 실행되어 감염으로 이어졌다. SmokeLoader는 Loader/Downloader 계열 악성코드로 감염된 PC에 자리 잡은 다음 공격자 서버와 통신하면서 추가 악성코드를 내려받아 실행하는 역할을 수행했다. 결론적으로 해당 사례는 여러 악성코드가 연계되어 실행되며 피해를 끼치는 실전적 구조를 보여준다.

4. 취약점 분석 개요

해당 취약점은 압축을 한 번 푸는 것보다 7-Zip File Manager에서 바깥 압축파일을 열고, 그 안의 안쪽 압축파일을 다시 연 다음, 최종 파일을 추출하는 흐름에서 Zone.Identifier 전파 여부를 검증하는 것이 핵심이다. 검증 순서는 Windows 10 VM 안에서 7-Zip 24.08 설치 후, 이중 압축파일을 생성하고, Zone.Identifier 붙인 뒤 취약한 7-Zip으로 압축 해제 후 내부 파일의 Zone.Identifier가 사라졌는지 확인하는 과정을 거쳐 진행하였다.

4.1 Zone.Identifier 전파 로직 분석

그림 3. [Zone.Identifier 스트림 이름 식별 로직]

본격적인 검증 이전 전파 로직을 분석한다. 해당 코드는 Windows의 Mark-of-the-Web 정보가 저장되는 NTFS ADS 이름인 ‘:Zone.Identifier’를 정의하고, 특정 스트림 이름이 Zone.Identifier인지 확인하는 역할을 한다. ‘k_ZoneId_StreamName_With_Colon_Prefix’는 ‘:Zone.Identifier’ 문자열을 상수로 선언한 부분이다. 이 값은 이후 원본 파일의 Zone.Identifier를 읽거나 추출 파일에 Zone.Identifier를 기록할 때 파일 경로 뒤에 붙는 스트림 이름으로 사용된다.

Is_ZoneId_StreamName() 함수는 전달받은 스트림 이름이 Zone.Identifier에 해당하는지 비교한다. 이때 대소문자를 구분하지 않는 비교 함수인 StringsAreEqualNoCase_Ascii()를 사용하여 Zone.Identifier 스트림 여부를 판단한다. 즉, 이 부분은 7-Zip이 파일의 ADS 중 MotW 정보에 해당하는 Zone.Identifier 스트림을 식별하기 위한 전처리 로직이다.

그림 4. [원본 파일의 Zone.Identifier 읽기 로직]

ReadZoneFile_Of_BaseFile() 함수는 원본 파일에 존재하는 Zone.Identifier 스트림을 읽어오는 역할을 한다. 함수는 먼저 버퍼를 초기화한 뒤, 전달받은 원본 파일 경로 ‘fileName’에 ‘:Zone.Identifier’ 문자열을 덧붙여 ADS 경로를 생성한다. 예를 들어 원본 파일이 outer.zip이라면 실제로 접근하는 경로는 outer.zip:Zone.Identifier가 된다.

이후 ‘NIO::CInFile’ 객체를 이용해 해당 ADS를 열고, 파일 크기를 확인한 뒤 그 내용을 버퍼에 저장한다. 코드에서는 파일 크기가 0이거나 일정 크기 이상인 경우 읽기를 중단하도록 처리하고 있으며, 정상적으로 읽은 경우 Zone.Identifier 내용이 buf에 저장된다. 이 버퍼는 이후 추출 파일에 MotW 정보를 다시 기록하기 위한 데이터로 사용된다. 따라서 이 함수는 Zone.Identifier 전파 과정 중 원본 압축파일의 MotW 정보를 읽는 단계에 해당한다.

그림 5. [추출 파일에 Zone.Identifier 쓰기 로직]

WriteZoneFile_To_BaseFile() 함수는 읽어온 Zone.Identifier 정보를 추출된 파일에 다시 기록하는 역할을 한다. 함수는 먼저 추출 대상 파일의 경로를 ‘fileName’으로 전달받고, 해당 경로 뒤에 ‘:Zone.Identifier’ 문자열을 붙여 ADS 경로를 생성한다. 예를 들어 추출된 파일이 benign.txt라면 실제 기록 대상은 benign.txt:Zone.Identifier가 된다.

이후 ‘NIO::COutFile’ 객체를 이용해 해당 Zone.Identifier 스트림을 생성하고, WriteFull() 함수를 통해 버퍼에 저장된 MotW 정보를 기록한다. 이 과정이 정상적으로 수행되면 추출된 파일에도 [ZoneTransfer], ZoneId=3과 같은 인터넷 출처 정보가 유지된다. 따라서 이 함수는 Zone.Identifier 전파 과정 중 추출 파일에 MotW 정보를 쓰는 단계에 해당하며, 원본 압축파일의 외부 출처 정보가 최종 추출 파일까지 유지되도록 하는 핵심 쓰기 로직이다.

‘ArchiveExtractCallback.cpp’에는 이렇게 Zone.Identifier ADS를 식별하고 원본 파일의 Zone.Identifier를 읽은 뒤 추출 파일에 다시 기록하는 ReadZoneFile_Of_BaseFile() 및 WriteZoneFile_To_BaseFile() 함수가 존재하며, 해당 함수들의 기능적 문제는 없다. 그러나 취약 버전에서는 사용자가 열린 압축파일 내부에서 또 다른 압축파일을 열고 그 내부 파일을 추출하는 경우, 이러한 전파 로직이 최종 파일에 정상적으로 이어지지 않아 MotW 정보가 누락될 수 있었다. 결국 공개된 CVE 설명과 7-Zip 24.09 릴리스 노트, 위의 전파 로직을 기준으로 볼 때 CVE-2025-0411은 특정 함수 한 줄의 오류라기보다 7-Zip File Manager의 중첩 압축파일 처리 경로에서 Zone.Identifier 전파 로직이 최종 추출 파일까지 적용되지 않은 흐름상의 취약점으로 판단된다.

4.2. PoC 분석

그림 6. [get_7zip_version()]


PoC 분석 대상은 7-Zip-CVE-2025-0411-PoC.py이다. 해당 스크립트는 CVE-2025-0411의 핵심 조건인 중첩 압축 구조를 자동으로 생성하기 위한 Python 기반 PoC이다.

get_7zip_version() 함수는 실습 환경에 설치된 7-Zip의 버전을 확인하기 위한 함수이다. 먼저 subprocess.run(["7z"], capture_output=True, text=True)를 통해 명령 프롬프트에서 7z 명령을 실행하고, 그 출력 결과를 문자열 형태로 저장한다. 이후 정규표현식 7-Zip (\d+).(\d+)을 사용하여 출력값에서 7-Zip의 주 버전과 부 버전을 추출한다. 버전 정보가 정상적으로 확인되면 이를 정수형으로 변환하여 (major, minor) 형태의 튜플로 반환한다. 예를 들어 7-Zip 24.08이 설치되어 있다면 (24, 8)을 반환한다. 만약 7-Zip이 설치되어 있지 않거나 PATH 환경변수에 등록되어 있지 않아 7z 명령을 실행할 수 없는 경우에는 FileNotFoundError 예외가 발생하며, 이때 오류 메시지를 출력하고 None을 반환한다. 따라서 이 함수는 이후 취약 버전 여부를 판단하기 위한 사전 단계로, 현재 시스템의 7-Zip 버전을 자동으로 식별하는 역할을 수행한다.

그림 7. [check_vulnerability(), compile_cpp()]


check_vulnerability() 함수는 앞서 확인한 7-Zip 버전이 CVE-2025-0411의 취약 버전에 해당하는지 판단하는 함수이다. 코드 상단에 정의된 VULNERABLE_VERSION_THRESHOLD = (24, 9)와 현재 설치된 7-Zip 버전 값을 비교하며, 버전이 24.09 미만인 경우 True를 반환한다. 즉, 7-Zip 24.08과 같이 24.09보다 낮은 버전은 취약한 환경으로 판단되고 24.09 이상 버전은 패치된 환경으로 판단된다.

이어서 compile_cpp() 함수는 PoC 내부에 포함될 실행 파일을 만들기 위해 C++ 소스 파일을 g++로 컴파일한다. 먼저 os.path.exists(source_file)을 통해 컴파일 대상 소스 파일이 실제로 존재하는지 확인하고 파일이 없을 경우 오류 메시지를 출력한 뒤 False를 반환한다. 소스 파일이 존재하면 subprocess.run()을 사용하여 g++ 컴파일 명령을 실행한다. 이때 source_file을 입력 파일로 사용하고, -o output_file 옵션을 통해 컴파일 결과 실행 파일의 이름을 지정한다. 또한 check=True 옵션을 사용하여 컴파일 과정에서 오류가 발생하면 예외가 발생하도록 처리한다. 컴파일이 정상적으로 완료되면 성공 메시지를 출력하고 True를 반환하며, 실패할 경우 subprocess.CalledProcessError 예외를 처리하여 실패 메시지를 출력한 뒤 False를 반환한다.

그림 8. [compress_file()]


compress_file() 함수는 PoC에서 중첩 압축 구조를 만들기 위한 핵심 함수이다. 해당 함수는 입력 파일의 존재 여부를 확인한 뒤 7-Zip 명령어 7z a를 호출하여 지정된 파일을 압축한다. 먼저 os.path.exists(input_file)을 통해 압축 대상 파일이 실제로 존재하는지 확인하고 파일이 존재하지 않을 경우 오류 메시지를 출력한 뒤 False를 반환한다. 입력 파일이 존재하면 subprocess.run(["7z", "a", output_archive, input_file], check=True)를 실행하여 7-Zip의 a명령으로 파일을 압축한다. 여기서 a는 archive에 파일을 추가하거나 새 압축파일을 생성하는 명령이며 output_archive는 생성될 압축파일 이름, input_file은 압축 대상 파일을 의미한다. 압축이 정상적으로 완료되면 성공 메시지를 출력하고 True를 반환, 압축 과정에서 오류가 발생하면 subprocess.CalledProcessError 예외를 처리하여 실패 메시지를 출력한 뒤 False를 반환한다.

그림 9. [main()]


main() 함수는 PoC 스크립트의 전체 실행 흐름을 제어하는 중심 함수이다. 먼저 get_7zip_version()을 호출하여 현재 시스템에 설치된 7-Zip 버전을 확인하고 버전 정보가 확인되지 않을 경우 실행을 종료한다. 이후 확인된 버전을 출력하고 check_vulnerability() 함수를 통해 해당 버전이 24.09 미만의 취약 버전인지 판단한다. 만약 취약 버전이 확인되면 사용자에게 계속 진행할지 묻고, 사용자가 동의한 경우에만 PoC 생성 절차를 수행한다. 반대로 24.09 이상 버전인 경우에는 취약하지 않은 환경으로 판단하고 실행을 종료한다. 이후 main() 함수는 executable.cpp를 compiled.exe로 컴파일하고 생성된 실행 파일을 first_compressed.7z로 1차 압축한다. 마지막으로 first_compressed.7z를 다시 double_compressed.7z로 2차 압축하여 중첩 압축 구조를 만든다. 이 구조는 CVE-2025-0411의 핵심 조건인 nested archive(중첩 압축 파일) 환경을 재현하기 위한 것으로 최종적으로 생성된 double_compressed.7z를 통해 7-Zip의 Mark-of-the-Web 전파 실패 여부를 실험할 수 있다.

4.3 MotW 전파 실패 검증

그림 10. [7-Zip 24.08 설치 확인]

취약 제품인 7-Zip 24.08을 Windows VM 안에 설치해 주었다.

그림 11. [이중 압축 파일 생성]

.txt 파일을 만들고 해당 파일을 이중으로 압축했다. PoC 파일 분석에서의 과정처럼 7-Zip의 a 명령어를 사용했다. 그 결과 outer.zip 내부에 inner.zip이 존재하며 제일 안쪽에 생성한 텍스트 파일 benign.txt이 존재하는 구조가 되었다. benign.txt는 실제 악성코드 대신 사용한 안전한 테스트 파일이다. 본 실습의 목적은 중첩 압축 해제 후 최종 파일에 ‘benign.txt:Zone.Identifier’ ADS가 존재하는지 확인하는 것이기 때문에, 추후 해당 내용을 검증하기 위해 생성되었다.

그림 12. [outer.zip에 Zone.Identifier 부착]

Zone.Identifier는 다운로드 방식으로 붙는 것이 일반적이지만, 해당 검증은 이중 압축 zip의 압축 해제 과정에서 MotW 전파 여부를 확인하는 것이 핵심 과제이며 텍스트 파일을 직접 만들어 사용했으므로 ZoneId=3을 수동으로 붙여주었다. Get-Content 확인 결과 성공적으로 부착된 것이 확인되었다.

그림 13. [7-Zip File Manager 실행]

GUI로 압축을 해제하기 위해 7-Zip File Manager를 실행하였다.

그림 14. [Propagate Zone.Id stream → Yes]

GUI에서 실행 후 도구(T) → 옵션(O) → 7-Zip 탭에 접속하여 7-Zip GUI의 Zone.Id 전파 옵션을 켜주었다.

그림 15. [7-Zip 24.08로 이중 압축 해제]

outer.zip을 열고 inner.zip을 더블 클릭하는 GUI 방식으로 benign.txt에 접근하여 압축 풀기 버튼을 눌러 C:\motw-lab\gui_2408\ 경로에 해당 파일을 추출하였다.

그림 16. [benign.txt에 Zone.Identifier 전파 여부 확인]

이중 압축을 전부 해제한 후 가장 먼저 만든 파일인 benign.txt에 Get-Item 확인 결과, Stream 영역에 ‘$DATA’가 존재할 뿐 Zone.Identifier는 찾아볼 수 없었다. 이를 통해 해당 파일이 악성 파일이었을 경우 중첩 압축 해제 과정에서 사라진 Zone.Identifier의 영향으로 보안 검사를 회피할 수 있다는 CVE-2025-0411 취약점을 검증하였다.


5. Patch

그림 17. [공식 7-Zip 변경 이력 24.09]

CVE-2025-0411의 패치는 단순 기능 개선이 아니라 중첩 압축파일에서 추출된 파일에 Windows의 Zone.Identifier ADS가 정상적으로 전파되도록 수정한 7-Zip 24.09의 보안 패치이다. 7-Zip의 공식 history 문서는 7-Zip 24.08 이하에서는 MotW가 부여된 외부 압축파일을 처리하는 과정에서 내부 파일이 인터넷 출처 정보를 상속하지 못할 수 있으나 24.09에서는 Zone.Identifier stream 전파 문제가 수정되었다고 명시하고 있다.

특히 강조된 줄은 22.0 버전 이후 존재한 기존의 Zone.Identifier stream 전파 ­snz 옵션을 사용하지 않고 7-Zip File Manager GUI에서 중첩 압축파일을 열고 추출할 때 Zone.Identifier가 전파되지 않던 버그를 수정한 것을 설명한다. 실질적으로 압축파일 해제는 명령줄이 아닌 GUI 환경에서 보편적으로 이루어지는 것을 감안하여 패치된 것을 알 수 있다.

그림 18. [7-Zip 24.09 설치 확인]

패치가 성공적으로 진행되었는지 확인하기 위해 이전 버전 제거 후 7-Zip 24.09 버전을 설치하였다. 패치 검증 역시 24.08 버전과 같은 방식으로 진행하였다.

그림 19. [7-Zip File Manager 실행]

GUI로 압축을 해제하기 위해 7-Zip File Manager를 실행했다.

그림 20. [Propagate Zone.Id stream → Yes]

실행 후 도구(T) → 옵션(O) → 7-Zip 탭에 접속하여 7-Zip GUI의 Zone.Id 전파 옵션을 켜주었다.

그림 21. [압축 해제 후 benign.txt 추출]

outer.zip을 열고 inner.zip을 더블 클릭하는 GUI 방식으로 benign.txt에 접근하여 압축 풀기 버튼을 눌러 C:\motw-lab\gui_2409\ 경로에 해당 파일을 추출하였다.

그림 22. [benign.txt Zone.Identifier 전파 확인]

추출한 benign.txt 파일 확인 결과 Stream에 $DATA(실제 파일 내용)와 Zone.Identifier이 모두 나타났다. 이는 ‘benign.txt:Zone.Identifier’ ADS가 존재함을 의미하며 정상적으로 Zone.Identifier가 전파된 것이다. 두 가지가 나타나는 이유는 NTFS 파일 하나 안에 스트림이 두 종류 있다는 뜻으로, -Stream * 명령어 옵션으로 해당 파일에 붙어 있는 모든 데이터 스트림을 보았기 때문이다. 두 가지 결과가 나타났다는 것은 정상적으로 MotW가 붙었다는 사실을 의미한다.

그림 23. [benign.txt ZoneId 확인]

마지막으로 benign.txt의 ZoneId를 확인한 결과, 태초에 부여한 3의 결과가 그대로 전파된 것을 검증할 수 있었다.


6. 결론

CVE-2025-0411 취약점은 그 자체만으로 즉시 시스템 장악이 이루어지는 유형은 아니지만 사용자가 외부 출처 파일임을 인지하지 못하게 만들어 악성 파일 실행 가능성을 높인다는 점이 특징이다. 특히 이중 압축파일과 문서 위장 기법이 결합될 경우 사용자는 정상 문서로 오인한 파일을 실행할 수 있으며, SmokeLoader와 같은 실제 공격 사례로 미루어 보았을 때 악성코드는 연계되어 사용되는 특성이 존재하고 해당 취약점이 그 시초가 될 수 있다. 따라서 본 취약점은 단순한 MotW 전파 오류가 아니라 사회공학적 공격과 악성코드 실행을 보조하는 보안 우회 취약점으로서 높은 위험도를 지닌다. 이에 따라 7-Zip 24.09 이상으로 업데이트하고 외부 압축파일의 출처 및 Zone.Identifier 유지 여부를 점검하는 대응이 필요하다.
